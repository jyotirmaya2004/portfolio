2.2 TYPOGRAPHY HIERARCHY
  - Primary Font Family: Inter (Google Font) - sans-serif, neutral, high-legibility.
  - Monospace Font: Geist Mono or System Mono (for tech tags, metadata, dates).
  - Type Scale:
     * Hero Title (H1):     32px - 60px (clamp / responsive), 700 bold, tracking -0.03em
     * Section Heading:     24px - 36px, 700 bold, tracking -0.02em
     * Subheadings (H2/H3): 18px - 22px, 600 semi-bold
     * Body Large:          18px - 20px, 400 regular, line-height 1.6
     * Body Regular:        15px - 16px, 400 regular, line-height 1.6
     * Caption / Metadata:  11px - 13px, 500 medium, uppercase or mono tracking

2.3 SURFACES, ELEVATION & GLASSMORPHISM
  - Border Radii: 8px to 16px on modern cards, 9999px (full pill) on badges/chips.
  - Glassmorphism effect:
     * Background: rgba(var(--bg-surface), 0.8) with backdrop-filter: blur(20px).
     * Border: 1px solid var(--border) with subtle gradient or ambient glow on hover.
  - Hover Motion: Subtle translateY(-4px to -6px), border color tinting to gold,
    ambient drop-shadow glow expansion.

2.4 THEME SWITCH TRANSITION
  - Smooth global CSS transition (350ms cubic-bezier) applied to background-color,
    border-color, text, fill, stroke, and box-shadow during toggle.
  - Anti-flash inline script in <head> checking localStorage('theme') and system
    prefers-color-scheme before render.

7. FLOATING CONTACT CHAT WIDGET ("LET'S TALK")
================================================================================
Purpose: Always-accessible, instant messaging drawer floating on all pages.

7.1 FLOATING LAUNCHER BUTTON
  - Position: Fixed bottom-right corner (bottom: 24px, right: 24px), z-index 50.
  - Appearance: Pill or circular gold button with message bubble icon.
  - Notification Dot: Emerald green pinging badge indicating "Available to talk".
  - Hover / Focus: Scales up with gold glow halo.

7.2 MODAL / SLIDE-OVER DRAWER DIALOG
  - Backdrop: Dark translucent backdrop overlay with click-to-dismiss functionality.
  - Mobile behavior: Bottom sheet modal sliding up from bottom edge.
  - Desktop behavior: Floating popover card anchored in bottom-right corner (width: ~380px-420px).
  - Accessibility & Controls:
     * Focus lock inside modal when opened (auto-focus on Name input).
     * Escape key dismisses modal.
     * Close "X" button in header.
     * Auto-closes on route change or browser history navigation.

7.3 FORM FIELDS & CLIENT-SIDE VALIDATION
  1. Name Field:
     - Type: Text, Required.
     - Bounds: 1 to 100 characters.
     - Placeholder: "Your Name".
  2. Email Field:
     - Type: Email, Required.
     - Validation: RFC-compliant regex pattern checking.
     - Placeholder: "your.email@example.com".
  3. Topic / Subject Field:
     - Type: Select or Text, Optional (e.g., "Collaboration", "Hiring", "General Inquiry").
  4. Message Field:
     - Type: Textarea, Required.
     - Bounds: Minimum 10 characters, maximum 2000 characters.
     - Placeholder: "Write your message here...".
  5. Honeypot Anti-Spam Trap:
     - Hidden input field (`name="honeypot"`, hidden via CSS/aria-hidden).
     - If populated by spam crawlers, submission is rejected silently.

7.4 FEEDBACK & SUBMISSION LIFECYCLE
  - Idle state: Clean inputs with subtle borders and clear focus rings.
  - Loading state: Submit button displays animated spinner, inputs disabled.
  - Success state: Form hides and displays checkmark animation:
     "Message Sent! Thanks for reaching out. I'll get back to you shortly."
     Includes a "Send Another Message" or "Close" button.
  - Error state: Inline alert banner in red/amber explaining exact validation or network issue.

8. BACKEND & API ARCHITECTURE
--------------------------------------------------------------------------------

8.1 CONTACT ENDPOINT — POST `/api/contact`
  - Payload Schema (JSON):
    {
      "name": string (1-100 chars, required),
      "email": string (valid email format, required),
      "topic": string (optional),
      "message": string (10-2000 chars, required),
      "honeypot": string (optional, must be empty)
    }

  - Security & Defenses:
     * IP Rate Limiting: Max 5 submissions per 10 minutes per IP address.
       Returns HTTP 429 Too Many Requests if exceeded.
     * Honeypot bot filtering: If honeypot is present, returns fake HTTP 200 without sending.
     * HTML entity sanitization: Strips and escapes HTML characters (<, >, &, ", ') to prevent XSS.

  - Email Service Dispatcher:
     * Integrated with Resend API (HTTP POST to https://api.resend.com/emails).
     * Generates responsive HTML email table + plain text fallback.
     * Sets visitor's email in Reply-To header so direct replies reach the sender.
     * Dev Mode Fallback: When EMAIL_API_KEY is unset (local development), prints clean
       mock email payload to console and succeeds gracefully.

  - Required Environment Variables:
     * `CONTACT_EMAIL`: Destination inbox address (e.g., hello@jyotirmayabehera.com)
     * `FROM_EMAIL`: Verified sender domain address (e.g., Portfolio <hello@verified-domain.com>)
     * `EMAIL_API_KEY` or `RESEND_API_KEY`: Secret Resend API key (re_...)

  - Sitemap: Dynamic Next.js route at `/sitemap.xml` registering all 7 routes:

  - Open Graph & Twitter Cards:
    * og:image: 1200x630px card image (`/og-image.jpg`).
    * Card type: `summary_large_image`.

9.2 ACCESSIBILITY (WCAG 2.1 AA)
  - Color contrast ratios exceed 4.5:1 for body copy and 3:1 for large display elements.
  - Keyboard navigation: Full focus-visible rings (2px solid gold with 2px offset).
  - ARIA attributes: Proper aria-label, aria-expanded, aria-controls, and role="img" / role="dialog".
  - Screen reader semantic heading order: Strict single H1 per page, followed by H2 and H3.
  - Respects `prefers-reduced-motion` media query (disables or accelerates all keyframes to 0.01ms).

9.3 PERFORMANCE TARGETS
  - Google Fonts Inter with `display: swap`.
  - Next.js Image component optimization with priority loading on hero avatars.
  - Zero heavy 3D library runtime bundle penalty (orbital math computed purely via CSS & SVG).
  - Stable scrollbar gutter (`scrollbar-gutter: stable`) to eliminate layout shifts.
